# Vision y Generacion de Imagenes con Foundry

Esta sesion es "Microsoft Foundry (III)" del temario: la primera mitad, centrada en vision. Primero repasamos como construir modelos de imagen a medida con Azure AI Custom Vision (el enfoque clasico, todavia vigente en Azure aunque el examen ya no lo detalla tanto como AI-900); despues vemos como Microsoft Foundry interpreta y genera contenido visual con modelos multimodales, que es lo que realmente evalua AI-901 en este bloque. El foco esta en conceptos y flujos de trabajo, no en codigo.

## 1. Objetivos de la sesion

- Entender los casos de uso de Azure Computer Vision.
- Explicar cuando usar un modelo de vision prediseñado frente a uno personalizado.
- Describir las capacidades de Azure AI Custom Vision.
- Entender el flujo basico para entrenar y desplegar un modelo de Custom Vision.
- Interpretar entradas visuales en prompts usando un modelo multimodal desplegado en Foundry.
- Generar nuevas salidas visuales con modelos generativos de imagen.

## 2. Servicios de Azure Computer Vision

- **Image Analysis:** modelo prediseñado para detectar objetos, escenas, etiquetas y generar descripciones.
- **OCR / Document Intelligence:** lee y extrae texto y estructura de imagenes y documentos.
- **Funciones relacionadas con rostros y personas:** detectan y analizan personas o rostros, sujeto a politicas de IA responsable y restricciones regionales.
- **Custom Vision:** permite construir tus propios modelos de clasificacion de imagenes o deteccion de objetos con etiquetas personalizadas.

## 3. Que es Azure AI Custom Vision

Custom Vision es un servicio de reconocimiento de imagenes basado en la nube: creas tus propios clasificadores de imagenes y detectores de objetos para tus propias categorias. Usa transfer learning por debajo, asi que no se parte de cero, y se expone mediante un portal web, APIs REST y SDKs para integrarlo en aplicaciones.

### Cuando usar Custom Vision

Usa el **Image Analysis prediseñado** cuando solo necesitas etiquetas, objetos o descripciones genericas y no te importan etiquetas de dominio muy especificas. Usa **Custom Vision** cuando tu escenario necesita clases personalizadas (logos de marca, defectos especificos, productos propios...), quieres control sobre las etiquetas, los datos de entrenamiento y los umbrales de rendimiento, o quieres desplegar en el edge con modelos compactos en dispositivos o IoT.

### Tipos de proyecto

- **Clasificacion de imagenes:** el modelo asigna una o varias etiquetas a toda la imagen. Ejemplo: clasificar la foto de un producto como "kit local", "kit visitante" o "kit de portero".
- **Deteccion de objetos:** el modelo localiza objetos con cajas delimitadoras. Ejemplo: detectar y contar todos los cascos en la imagen de una obra.

### Clasificacion multiclase vs multietiqueta

En la **clasificacion multiclase**, cada imagen pertenece a exactamente una clase (por ejemplo, una camiseta es "local", "visitante" o "portero", una sola etiqueta). En la **clasificacion multietiqueta**, cada imagen puede tener varias etiquetas a la vez (por ejemplo, una imagen puede contener "jugador", "balon", "cesped" y "publico" simultaneamente).

### Dominios y modelos compactos

Custom Vision ofrece **dominios**: variantes de modelo pre-optimizadas para tipos de imagen especificos (generico, alimentacion, retail, etc.); se puede cambiar de dominio y reentrenar para ver si mejora la precision. Los **dominios compactos** son modelos mas pequenos, optimizados para exportar a moviles o dispositivos edge, utiles cuando se necesita inferencia offline o en el propio dispositivo.

## 4. El flujo de trabajo de Custom Vision

1. Crear los recursos de Training y Prediction en Azure.
2. En el portal de Custom Vision, crear un proyecto (elegir clasificacion/deteccion y dominio).
3. Subir imagenes y etiquetarlas con las etiquetas correctas.
4. Entrenar el modelo para producir una iteracion.
5. Evaluar metricas y predicciones de muestra.
6. Cuando el resultado es satisfactorio, publicar la iteracion en un endpoint de prediccion o exportar el modelo.

### Datos y etiquetado

Se recomienda empezar con al menos decenas de imagenes por etiqueta (unas 50 es una guia habitual), usando imagenes que reflejen la variabilidad real (iluminacion, angulos, fondos, dispositivos) y manteniendo las clases razonablemente equilibradas en numero de imagenes. Para deteccion de objetos, las cajas delimitadoras deben ser precisas y consistentes. Revisar y corregir etiquetas incorrectas es clave: los errores de anotacion perjudican mucho el rendimiento.

### Evaluar el modelo

Tras entrenar, Custom Vision muestra **precision** ("de las imagenes predichas como positivas, cuantas son realmente correctas") y **recall** ("de todos los positivos reales, cuantos detecto el modelo"); para deteccion de objetos se usan metricas como Average Precision (AP/mAP). Se puede inspeccionar el rendimiento por etiqueta para identificar clases que necesitan mas datos, y revisar predicciones de muestra para ver aciertos y fallos reales, no solo numeros.

Para mejorar el modelo de forma iterativa: recopilar mas imagenes para las clases debiles o casos poco frecuentes, anadir casos dificiles (oclusiones, angulos inusuales, mala iluminacion), limpiar etiquetas incorrectas o inconsistentes, probar otro dominio si los resultados son pobres, y reentrenar comparando la nueva iteracion con las anteriores.

### Despliegue y uso

En la nube, se publica una iteracion y se obtiene una URL y una clave de prediccion, que se puede llamar desde web, movil, backend o herramientas no-code. En el edge, se exportan modelos compactos para apps moviles, sistemas embebidos o dispositivos IoT. Ejemplos de integracion: control de calidad en fabricas, camaras inteligentes, apps de inspeccion movil o Power Apps.

:::info Importante para el examen
Precision responde a "de lo que predije como positivo, cuanto era correcto"; recall responde a "de todo lo que era realmente positivo, cuanto detecte". No los confundas.
:::

## 5. Vision multimodal en Microsoft Foundry

AI-901 pone el foco en un enfoque distinto al de Custom Vision: en lugar de entrenar un clasificador propio, se usa un **modelo multimodal** (que entiende texto e imagen a la vez) ya desplegado en Foundry, y se le pasa una imagen dentro del propio prompt.

- **Interpretar entradas visuales:** se envia una imagen (o varias) junto con una instruccion de texto al modelo multimodal — por ejemplo, "describe lo que ves en esta imagen" o "extrae la matricula de este coche" — y el modelo responde combinando ambas modalidades, sin necesidad de entrenar nada previamente.
- **Casos de uso tipicos:** describir el contenido de una foto, responder preguntas sobre una imagen (visual question answering), comparar varias imagenes, o servir de primer paso para clasificacion o deteccion cuando no merece la pena entrenar un modelo de Custom Vision a medida.
- **Cuando preferir esto sobre Custom Vision:** cuando las categorias no estan fijadas de antemano, cuando se necesita razonar sobre la imagen (no solo etiquetarla), o cuando no hay presupuesto de tiempo para recopilar y etiquetar un dataset propio.

### Generacion de imagenes

Foundry tambien da acceso a **modelos generativos de imagen**, que crean contenido visual nuevo a partir de una descripcion en texto (text-to-image) o a partir de una imagen de partida (edicion, variaciones, expansion de la escena). Al igual que con los modelos de texto, se prueban primero en el playground del modelo, ajustando el prompt y parametros como el tamano o el estilo de salida, antes de integrarlos en una aplicacion.

:::tip Para el examen
AI-901 evalua "interpretar" y "generar" contenido visual con modelos multimodales/generativos de Foundry, no los detalles de entrenamiento de Custom Vision. Custom Vision sigue siendo un servicio real y util en Azure, pero ya no es el centro de gravedad del examen — dedicale mas tiempo de estudio a la parte de Foundry.
:::
